## 1. 임베딩 (Embedding)

문장을 숫자 벡터(좌표)로 바꾸는 것. 핵심 성질은 하나다: **의미가 비슷한 문장은
가까운 좌표를 받는다.**

```
"사용자는 아메리카노를 좋아한다"   → (0.81, 0.12, …)
"사용자는 커피를 즐겨 마신다"      → (0.79, 0.15, …)   ← 위와 가깝다
"사용자는 등산을 시작했다"         → (0.11, 0.88, …)   ← 위 둘과 멀다
```

실제 벡터는 수백~수천 차원이지만, 직관은 2차원 지도로 충분하다: 임베딩은 "의미의
지도" 위에 문장을 꽂는 것이고, 관련된 이야기일수록 같은 동네에 모인다. 이
시스템에서 모든 노드는 내용과 함께 임베딩을 저장하며, "비슷한 기억 찾기"는 전부
이 좌표 위에서의 거리 계산이다.

## 2. 코사인 유사도 (Cosine Similarity)

두 벡터가 얼마나 같은 방향을 보는지의 척도. 두 벡터 사이 각도의 코사인 값이다.

- **1.0** — 완전히 같은 방향 (사실상 같은 의미)
- **0.9 안팎** — 거의 같은 이야기의 재표현
- **0.5~0.7** — 관련은 있는 다른 이야기
- **0 근처** — 무관

거리 대신 각도를 쓰는 이유: 벡터의 길이(문장의 길이나 강조 정도에 영향받는 값)를
무시하고 **방향(의미)만** 비교하기 위해서다.

주의할 성질 하나 — 코사인 유사도는 **표면 의미에 민감하고 극성에 둔감하다**.
"커피를 좋아한다"와 "커피를 못 마시게 됐다"는 반대 의미인데도 둘 다 '커피에 대한
취향 진술'이라 높은 유사도를 받는다. 본문의 게이트가 회색지대(판단 유예)를 두는
이유가 정확히 이 맹점이다.

## 3. kNN (k-Nearest Neighbors, k-최근접 이웃)

"주어진 점에서 **가장 가까운 k개**를 찾아라" — 그게 전부다. 이 시스템에서는
"기준 문장의 임베딩과 코사인 유사도가 가장 높은 기존 노드 k개"를 뜻한다.

```
신규 문장: "사용자는 라떼를 자주 마신다"     (k = 3일 때)

기존 노드                          유사도
"아메리카노를 좋아한다"            0.88   ← 1등 이웃
"커피를 즐겨 마신다"               0.85   ← 2등 이웃
"카페에서 일하는 걸 좋아한다"      0.64   ← 3등 이웃
"등산을 시작했다"                  0.12   (탈락)
```

이 시스템은 kNN을 두 군데서 쓴다:

- **게이트(쓰기)** — 신규 후보의 최근접 이웃들을 조회해 중복인지(1등의 유사도),
  이웃 가설을 깔지(하한 이상의 k개)를 판정한다.
- **인출 시드(읽기)** — 쿼리의 최근접 노드 k개를 랭킹의 출발점으로 삼는다.

**임계값 컷과의 차이**가 중요하다. "유사도 0.7 이상만 반환"(임계값 컷)은 조건을
만족하는 것이 0개일 수도 100개일 수도 있다 — 기아와 홍수. "가장 가까운 k개"(kNN)는
**항상 정확히 k개**를 준다. 본문이 임계값 방식을 버리고 top-k + 랭킹으로 간 이유다.

## 4. 지수 감쇠와 반감기 (Exponential Decay, Half-life)

"매일 같은 **비율**로 줄어드는" 감소 방식. 수식 `e^(−λt)`에서 λ가 그 비율을,
t가 경과 시간을 뜻한다.

직관은 반감기로 잡는 게 쉽다 — 값이 절반이 되는 데 걸리는 시간:

```
반감기 = ln(2) / λ ≈ 0.693 / λ

λ = 0.01  →  반감기 약 69일
λ = 0.02  →  반감기 약 35일
λ = 0.05  →  반감기 약 14일
λ = 0     →  감쇠 없음 (영원히 그대로)
```

이 시스템에서 t는 "태어난 후 시간"이 아니라 **"마지막 강화 이후 시간"**이다.
강화(bump)가 일어나면 시계가 0으로 리셋되므로, 감쇠는 나이가 아니라 **방치된
시간**에 비례한다. 자주 쓰이는 기억은 시계가 계속 리셋되어 가라앉지 않는다.

부수 성질 하나(본문의 "저장값을 깎는 배치가 필요 없다"의 근거): 지수 감쇠는
**무기억(memoryless)**이다 — 90일치 감쇠를 한 번에 계산하나, 30일씩 세 번 나눠
계산하나 결과가 같다. 그래서 중간중간 저장값을 갱신해둘 필요 없이, 읽는 순간
경과 시간 전체를 수식에 넣으면 언제나 정확한 값이 나온다.

## 5. 가중합 점수 (Weighted Sum)

여러 신호를 하나의 순위로 합치는 가장 단순한 방법:

```
score = 가중치₁ × 신호₁ + 가중치₂ × 신호₂ + …
```

각 신호는 [0, 1] 범위의 "떠올릴 이유"이고, 가중치는 그 이유를 얼마나 중요하게
칠지의 배율이다. 가중치를 0으로 두면 그 이유를 끄는 것과 같다. 본문의
`score = α·유사도 + β·엣지활성 + γ·최근성 + δ·노드강도`가 정확히 이 구조다.

## 6. 그래프 용어

- **노드(node)** — 점. 여기서는 기억 하나.
- **엣지(edge)** — 두 점을 잇는 선. 여기서는 두 기억의 관계.
- **방향** — 엣지는 저장할 때 `A → B`로 방향을 갖지만, 이 시스템의 인출은 방향을
  무시하고 양쪽으로 읽는다(무방향 읽기). 방향은 저장 시의 중복 방지 키로만
  기능한다.
- **1-hop** — "한 다리 건너". 어떤 노드에서 엣지 하나로 닿는 이웃까지가 1-hop,
  이웃의 이웃이 2-hop이다. 본문의 인출은 시드에서 1-hop까지만 확장한다 — 그래프
  전체를 걷지 않고, 지금 쿼리가 밝힌 지점의 한 다리 옆까지만 본다.
