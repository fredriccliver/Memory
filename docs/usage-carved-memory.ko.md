# 사용이 조각하는 메모리 (Usage-Carved Memory)

> 이 문서는 이 패키지의 저장·인출 시스템 v1의 **원리**를 설명한다. 대상 독자는 이
> 패키지를 사용하거나 내부를 이해하고 싶은 개발자다. 코드 레퍼런스가 아니라 설계
> 설명서이며, 구현된 부분만 다룬다.
>
> 문서에 등장하는 구체적 수치(임계값·가중치 등)는 전부 **설명용 예시값**이다. 실제
> 값은 애플리케이션이 튜닝 파라미터로 주입하며, 기본값은 `src/tuning.ts`가 정의한다.
>
> 이 시스템은 특정 종류의 서비스를 전제하지 않는다. 대화형 어시스턴트든, 코딩
> 에이전트의 세션 기억이든, "엔티티에 대한 사실이 쌓이고 다시 인출되는" 곳이면
> 동일하게 적용된다. 본문의 "대화"는 상호작용 로그 일반(메시지, 세션 기록 등)을
> 가리키는 말로 읽으면 된다.
>
> 임베딩, 코사인 유사도, kNN, 지수 감쇠 같은 용어가 낯설다면 개념 부록을 먼저
> 읽는 것을 권한다: [usage-carved-memory-concepts.ko.md](./usage-carved-memory-concepts.ko.md)

## 1. 배경 — 왜 score 기반 인출인가

LLM의 외부 메모리는 두 가지 힘 사이에 있다.

- **기억은 쌓일수록 가치가 있다.** 노드를 지우는 순간 "오래 함께한 기억"이라는
  자산이 사라진다. 그래서 이 시스템은 노드를 삭제하지 않는 것을 전제로 한다.
- **기억은 쌓일수록 다루기 어렵다.** 보유량 N이 커질수록, "전체를 읽고 정리한다"는
  종류의 접근(전량 재구성, 전체 클러스터링, 전체 감쇠 배치)은 비용이 N에 비례해
  폭발한다.

이 긴장을 푸는 원칙이 이 시스템의 이름이다: **그래프의 "정답"을 계산하지 않는다.
사용이 조각한다.**

- 어떤 LLM 호출도 그래프 전체를 보지 않는다. LLM 비용은 보유량 N이 아니라
  **변화량 ΔN**에 비례한다.
- 후보 생성은 벡터·SQL이 하고, 확정만 LLM이 한다. 모든 LLM 호출의 컨텍스트는
  O(1)이다.
- 엣지는 정답이 아니라 **가설**이다. 싸게 깔고, 사용이 강화하고, 미사용이
  가라앉힌다.
- 판단은 소프트(랭킹)라서 가역이다. 틀린 판단의 비용이 낮아야 저가형 모델과 값싼
  규칙을 쓸 수 있다 — 오류를 흡수하는 설계.
- **망각은 삭제가 아니라 인출 랭킹의 항이다.** 어떤 배치 작업도 전체 행을 만지지
  않는다.

이 원칙 아래에서 인출은 자연히 "임계값을 넘는 것을 모두 반환"이 아니라 **"지금 이
순간 떠올릴 가치가 가장 큰 상위 N개를 선발"** 이 된다. 그 선발 기준이 score다.

임계값 컷 방식에는 구조적 실패 모드가 둘 있다. 관련 기억이 임계값을 못 넘으면
아무것도 반환되지 않고(기아), 임계값 근처에 비슷한 기억이 몰려 있으면 잡음이
쏟아진다(홍수). score 랭킹 + 상위 N 선발은 두 실패 모드가 없다 — 항상 "지금 가장
나은 N개"가 나온다.

## 2. 데이터 모델

### 노드 (memories)

기억의 단위. 자연어 한 문장~한 단락의 사실이다.

| 필드 | 의미 |
|---|---|
| `content` | 기억 내용 (자연어) |
| `embedding` | 내용의 벡터. 내용이 갱신되면 재생성된다 |
| `strength` | 저장 강도 [0, 1]. 재언급될수록 오른다 |
| `strength_updated_at` | 강도가 마지막으로 갱신된 시각 — **감쇠의 시계** |
| `retrieval_count`, `last_retrieved_at` | 사용 기록. 인출될 때마다 적힌다 |

### 엣지 (edges)

두 기억 사이의 관계 가설. 자연키는 `(from, to, type)`이며 방향이 있지만, 인출은
무방향으로 읽는다.

| 필드 | 의미 |
|---|---|
| `origin` | 누가 만들었나 — `conversation`(맥락 확정) 또는 `knn_seed`(임베딩 가설) |
| `strength` | 저장 강도 [0, 1]. 태어난 확신 수준에서 시작해 사용으로 오른다 |
| `strength_updated_at` | 감쇠의 시계. 강화될 때마다 리셋된다 |

`origin`에 대해 중요한 것 하나: **소비 단계(랭킹·강화·감쇠)는 origin을 보지
않는다.** origin은 행동을 바꾸는 타입이 아니라 자동 기록자의 서명이다 — 어떤 자동
프로세스(게이트, 마이그레이션 등)가 쓴 행인지 식별할 수 있어야, 그 프로세스가
잘못됐을 때 출력을 한몫에 되돌릴 수 있다.

개념적으로 두 origin의 차이는 "누가 후보를 찾았나"가 아니라 **"맥락의 확정을
통과했는가"** 다:

- `conversation` — 대화를 읽은 LLM이 "이 두 기억은 실제로 관련 있다"고 확정한
  링크. 확정급의 고정 강도로 태어난다.
- `knn_seed` — 임베딩 유사도만 보고 깔린 미확정 가설. 유사도를 그대로 강도로
  받아 태어나고, 이후 사용이 검증한다.

### 강도와 유효 강도

저장 강도는 쓰기 시점의 값이고, 랭킹이 실제로 읽는 값은 **유효 강도**다:

```
유효강도 = 저장강도 × e^(−λ × 마지막_강화_이후_경과일)
```

λ(감쇠 상수)가 0이면 망각이 꺼진 상태다. λ > 0이면 강화받지 못한 채 흐른 시간만큼
가라앉는다. 이 계산은 **읽기 시점의 수식**이다 — 저장값을 깎는 배치 작업은
존재하지 않으며, 존재할 필요가 없다. 이것이 "망각 = 랭킹의 항"의 구현이다.

> **관측 시 주의**: DB를 직접 조회하면 보이는 것은 저장 강도다. 오래 운영된
> 엔티티에서는 자주 쓰인 엣지들이 상한(1.0) 근처에 몰려 "다 똑같아" 보일 수
> 있는데, 시스템이 실제로 소비하는 값은 유효 강도이며 이는 사용 주기에 따라
> 연속적으로 갈라져 있다. 시각화·분석·디버깅은 저장값이 아니라 유효 강도
> (`effectiveStrength()` 또는 위 수식)를 기준으로 하라. 저장값과 시계는 "마지막
> 강화 시점의 확신 + 그 시각"이라는 원본 기록이고, 유효값은 언제든 그로부터
> 계산되는 파생값이다.

## 3. 쓰기 — 중복 게이트 (삽입 시점)

애플리케이션이 대화를 던지면, 패키지의 추출 LLM이 저장할 사실들을 뽑는다. 각
후보는 저장되기 직전에 **게이트**를 통과한다: 기존 기억 중 최근접 이웃 top-K를
벡터로 1회 조회하고(이때 계산한 임베딩은 저장 시 재사용된다), 최근접 유사도가
어느 밴드에 떨어지는지로 운명이 갈린다.

```
                 유사도
  1.0 ┬─────────────────────────
      │  스킵 밴드: "이미 있는 기억이다"
      │  → 생성하지 않는다. 대신 기존 노드의 strength를 올린다(재언급 = 강화 신호)
 skip ┼─────────────────────────
      │  회색지대: "같은 건지 애매하다"
      │  → 일단 생성하고, 최근접과 강한 링크를 걸고, 병합 심사 큐에 적는다(판단 유예)
 link ┼─────────────────────────
      │  시딩 밴드: "새 사실이되, 이웃일 후보들이 있다"
      │  → 생성하고, 시딩 하한 이상의 top-K 이웃과 knn_seed 엣지를 깐다
      │    (강도 = 유사도)
 floor┼─────────────────────────
      │  무연결: 생성만
  0.0 ┴─────────────────────────
```

각 밴드의 논리:

- **스킵 밴드** — 거의 동일한 문장의 재등장은 버그가 아니라 신호다. 같은 사실이
  다시 언급됐다는 것은 그 기억이 중요하다는 뜻이므로, 중복 노드를 만드는 대신
  기존 노드를 강화한다. 정보 손실은 없다 — 스킵되는 내용은 정의상 기존 노드에
  이미 있다.
- **회색지대** — 임베딩은 극성에 둔감하다. "커피를 좋아한다"와 "커피를 못 마시게
  됐다"는 표면이 비슷해 높은 유사도를 받지만 의미는 반대다. 이 밴드에서
  스킵하면 위험하므로, 생성은 하되 두 노드를 강한 링크로 묶고 "나중에 내용을
  읽고 심사하라"는 장부(sleep_jobs)에 적는다. 지금 판단하지 않는 것이 판단이다.
- **시딩 밴드** — 새 사실이지만 주변에 관련 후보들이 있다. 이들과의 링크가 진짜
  의미 있는지는 아무도 모른다 — 그래서 가설로 싸게 깔아둔다. 맞는 가설은 사용이
  강화할 것이고, 틀린 가설은 쓰이지 않아 가라앉을 것이다. 깔아두는 비용은 0에
  가깝다(게이트가 이미 계산한 top-K 결과를 재사용하므로 추가 조회가 없다).

### 맥락 엣지의 형성

시딩과 별개로, 추출 LLM은 "이번에 인출된 기존 기억 목록" 안에서 신규 사실과 실제
관련 있는 기억을 지목할 수 있다. 이렇게 형성되는 것이 `conversation` 엣지다.
흐름을 접으면:

1. 인출 시점에 **임베딩**이 후보(작업 세트)를 골랐고,
2. 추출 LLM이 대화 **맥락** 안에서 그중 진짜 관련을 확정했다.

즉 맥락 엣지도 후보는 임베딩이 댔다. `knn_seed`와의 차이는 확정 단계의 유무뿐이다.
추출 LLM은 인출 경계 밖의 기억과는 링크를 만들 수 없다 — 그 사각지대를 메우는
것이 시딩이고, 시딩된 가설을 검증하는 것이 사용이다.

### 충돌 정책 — 강도는 오르기만 한다

같은 `(from, to, type)` 쌍에 대한 삽입이 충돌하면: **강도는 더 큰 값으로만
갱신되고, origin은 최초 작성자의 것이 보존된다.** 예를 들어 맥락 엣지가 먼저
생긴 쌍에 더 높은 유사도의 시드 삽입이 겹치면, 강도만 오르고 origin은
`conversation`으로 남는다. 임베딩 신호는 맥락 엣지를 강화할 수는 있어도
약화시키거나 재분류할 수 없다 — 쓰기 권한의 서열이 구조로 강제된다.

엣지를 지우거나 약화시키는 권한은 맥락(추출 LLM의 링크 제거 판정)에만 있다.

## 4. 읽기 — score 랭킹 인출

### 후보군: 시드 + 1-hop 확장

쿼리(현재 상호작용의 최근 맥락)가 들어오면:

1. **벡터 시드** — 쿼리 임베딩으로 top-k 노드를 뽑는다. 임계값 컷이 아니라 항상
   k개를 뽑는다.
2. **1-hop 확장** — 각 시드에 엣지로 붙어 있는 이웃 노드를 후보에 추가한다.
   방향은 무시한다(무방향 읽기).

후보군 = 시드 ∪ 시드의 이웃. 그래프 전체를 보지 않고, 지금 쿼리가 밝힌 지점의
1촌까지만 본다.

### score — 네 가지 "떠올릴 이유"의 가중합

각 후보는 다음 점수를 받는다:

```
score = α·유사도 + β·엣지활성 + γ·최근성 + δ·노드강도

  유사도   = cos(쿼리, 노드)                      … "지금 얘기와 직접 관련 있다"
  엣지활성 = max(유효엣지강도 × 해당 시드의 유사도) … "지금 떠오른 것과 연결돼 있다"
  최근성   = e^(−생성_후_경과일 / 스케일)          … "최근에 생긴 기억이다"
  노드강도 = 노드의 유효강도                       … "자주 확인된 기억이다"
```

각 항이 존재하는 이유:

- **α (유사도)** — 검색의 축. 이것만 있으면 시스템은 검색엔진이다.
- **β (엣지활성)** — 연상의 축. 시드 노드가 강하게 당길수록, 그리고 그 시드
  자체가 쿼리와 관련 있을수록 이웃이 함께 떠오른다. 유효엣지강도와 시드
  유사도의 **곱**이라는 점이 중요하다 — 강한 엣지라도 시드가 쿼리와 무관하면
  견인력이 없고, 시드가 정확해도 엣지가 약하면 딸려오지 않는다. 이웃이 여러
  시드와 연결돼 있으면 가장 강한 통로 하나(max)만 인정한다.
- **γ (최근성)** — 시사성의 축. 방금 생긴 기억은 지금 대화와 관련 있을 확률이
  높다. 노드의 **생성 시각** 기준이다.
- **δ (노드강도)** — 검증의 축. 여러 번 재언급된 기억은 그 인물·주제의 핵심일
  확률이 높다. 쿼리와 무관하게 작동하는 유일한 항이다.

γ와 δ·β의 시간축이 다르다는 점을 눈여겨보라. γ는 "태어난 지 얼마나 됐나"(고정
스케일), 감쇠는 "마지막으로 강화된 지 얼마나 됐나"(λ 다이얼)다. 갓 태어난 기억의
우대는 γ가, 잊혀가는 기억의 침강은 λ가 맡는다.

### 선발과 부수효과

score 내림차순으로 상위 N개가 선발되어 애플리케이션에 반환된다 — 이것이 이번
턴에 시스템이 "떠올리는" 작업 기억이다. score의 성질:

- **저장되지 않는다.** 매 인출마다 그 순간의 쿼리·시각 기준으로 재계산된다.
  감쇠가 배치 없이 성립하는 이유다.
- **절대값은 무의미하다.** 상대 순위만 쓰며, 임계값 컷이 없으므로 "아무것도 안
  떠오르는" 실패 모드가 없다.

선발 직후 두 가지 사용 신호가 비동기로 기록된다(인출 응답을 막지 않는다):

- 선발된 노드들의 `retrieval_count`·`last_retrieved_at` 갱신
- **선발에 기여한 엣지들의 강도 bump** — β항의 통로로 실제 쓰인 엣지가 조금
  강해지고, 감쇠 시계가 리셋된다

이 부수효과가 다음 인출의 score를 바꾼다. **오늘의 선발이 내일의 선발을 만든다** —
자기강화 고리이며, 여기에 λ가 반대 방향 힘으로 걸려 균형을 잡는다.

---

## 5. 조각 — 강화와 감쇠

강화 신호는 두 축으로 분리되어 있다:

| 신호 | 대상 | 발생 시점 | 의미 |
|---|---|---|---|
| 재언급 bump | **노드** | 게이트가 스킵 판정할 때 | "이 사실이 다시 언급됐다" |
| 사용 bump | **엣지** | 랭킹 인출에 기여했을 때 | "이 연결이 실제로 쓸모 있었다" |

노드 강도는 그 기억 자체의 확인된 무게이고, 엣지 강도는 관계의 검증된 유용성이다
— 별개의 영구 상태다. 인출된다고 노드 강도가 오르지는 않는다(사용 기록만 적힌다).
기억을 강하게 만드는 것은 재언급, 연결을 강하게 만드는 것은 사용이다.

감쇠는 λ 하나로 노드·엣지 전부에 공평하게 작동한다. 그 결과:

- **계속 쓰이는 것** — bump가 시계를 계속 리셋하므로 유효강도가 유지된다. 저장
  강도가 상한(1.0)에 닿아도 시계 리셋은 계속 유효하다. 상한에 닿은 것들
  사이에서는 저장값이 더 이상 변별하지 못하지만, λ가 켜진 환경에서는 **사용
  주기가 변별을 이어받는다** — 매일 쓰이는 1.0과 한 달 방치된 1.0의 유효강도는
  전혀 다르다. 장기적으로 변별의 축은 "저장된 크기"에서 "사용의 최근성"으로
  이동하며, 이것이 이 설계의 의도된 종착점이다.
- **안 쓰이는 것** — 아무 쓰기 없이 유효강도가 지수적으로 가라앉는다. 랭킹에서
  보이지 않게 되는 것이지 삭제되는 것이 아니다.
- **부활** — 가라앉은 엣지가 어느 날 다시 인출에 기여하면, bump가 시계를
  리셋하면서 저장 강도 그대로 즉시 복귀한다. 저장값을 깎지 않기 때문에 부활이
  싸다 — 틀린 침강의 비용이 낮다는 뜻이고, 이것이 오류 흡수 설계다.

살아남는 것의 정의는 결국 **bump 유입 속도가 감쇠 속도를 이기는 것**이다. λ는 그
균형점을 정하는 다이얼이다.

## 6. 변수 사전 — 역할과, 올리고 내리는 것의 의미

값 자체는 애플리케이션이 주입한다. 여기서는 각 다이얼이 시스템의 어떤 성질을
움직이는지만 적는다.

### 게이트 (쓰기 — 무엇이 기억이 되는가)

| 변수 | 역할 | 올리면 | 내리면 |
|---|---|---|---|
| 스킵 임계값 | "이미 있는 기억" 판정선 | 스킵이 줄어 중복이 늘어난다. 안전하지만 그래프가 지저분해진다 | 스킵이 늘어난다. 과하면 정보 델타가 있는 변형(세부가 추가된 재진술)까지 흡수되어 기억이 손실된다 |
| 회색지대 하한 | "애매함" 판정선 | 회색지대가 좁아져 심사 유예가 줄고 대부분 그냥 생성된다 | 회색지대가 넓어져 심사 큐 적재와 강한 링크가 늘어난다. 심사 처리량과의 트레이드 |
| 시딩 유사도 하한 | 가설을 깔 최저 유사도 | 그래프가 성기고 깨끗해진다. 연상 견인력 감소 | 약한 가설까지 깔린다. β가 넓게 더듬지만 잡음과 행 수 증가 |
| 시드 최대 개수 | 노드당 가설 수 상한 | 그래프 밀도 증가 — 잠자기·감쇠가 칠 잡초도 증가 | 확실한 이웃만 연결 |

세 판정선의 서열은 항상 `스킵 임계값 > 회색지대 하한 > 시딩 하한`이어야 하며,
패키지의 검증기가 위반 시 기본값으로 폴백한다.

### 랭킹 (읽기 — 무엇이 소환되는가)

| 변수 | 올리면 | 내리면 |
|---|---|---|
| α (유사도) | 쿼리 직결 위주 — 검색엔진에 가까워진다 | 유사도가 낮아도 연결·강도로 올라온다 — 연상 위주 |
| β (엣지활성) | 시드의 이웃이 강하게 딸려온다 — "하나 떠올리면 묶음이 온다". 과하면 한 시드의 이웃이 목록을 장악한다 | 그래프를 무시한다 — 엣지에 투자한 모든 것이 무의미해진다 |
| γ (최근성) | 갓 생긴 기억 우대 — 최신 화제 민감. 과하면 오래된 핵심 사실이 밀린다 | 생성 시점 무관 — 어제와 작년이 동급 |
| δ (노드강도) | 자주 재언급된 기억이 모든 쿼리에서 우대 — "그 사람 하면 떠오르는 것" 효과. 과하면 인기 노드가 만능 답이 된다 | 재언급 이력이 인출에 반영되지 않는다 |
| λ (감쇠 상수) | 미사용 기억·연결이 빨리 가라앉는다. 그래프 자정 속도 증가. 과하면 재언급 없는 확립된 사실까지 침강 | 0이면 망각이 꺼진다 — 한 번 얻은 강도가 영구 |

λ에 대한 안전 성질 하나: λ는 β와 δ에만 작용하고 **α와 γ는 건드리지 않는다**.
아무리 감쇠가 진행돼도, 쿼리와 직접 관련된 오래된 기억은 유사도로 여전히
소환된다. λ가 죽이는 것은 *연상 경로*이지 *검색 경로*가 아니다.

### 패키지 내부 상수 (튜닝 비노출)

출생 강도에는 서열이 있다: **맥락 확정 > 회색지대 링크 > 시딩 하한**. 확정된
관계가 어떤 가설보다도 강하게 태어나는 것이 아니라 — 시드는 유사도가 높으면
확정급을 넘을 수도 있다 — 최소 보장선의 서열이다. bump 폭도 두 종류다: 재언급
bump(노드)가 사용 bump(엣지)보다 크다. 한 번의 명시적 재언급이 한 번의 암묵적
사용보다 강한 신호이기 때문이다.

## 7. 시나리오

예시 수치는 전부 설명용이다.

### 7.1 삽입 — 세 문장의 운명

기존 기억: M1 "사용자는 아메리카노를 좋아한다", M2 "사용자는 카페에서 일하는 걸
좋아한다".

- 후보 A "사용자는 아이스 아메리카노를 좋아한다" — M1과 유사도 0.98(스킵 밴드).
  **생성되지 않는다.** M1의 노드 강도가 오른다. 대화가 같은 취향을 다시 확인해준
  것으로 처리된다.
- 후보 B "사용자는 커피를 못 마시게 됐다" — M1과 0.91(회색지대). 표면은
  비슷하지만 극성이 반대일 수 있다. **생성되고**, M1과 강한 링크로 묶이며, 병합
  심사 장부에 (B, M1, 0.91)이 적힌다. 이 쌍의 진실(모순? 갱신? 양립?)은 나중에
  내용을 읽는 심사가 가린다.
- 후보 C "사용자는 등산을 시작했다" — 최근접 M2와 0.72(시딩 밴드). **생성되고**,
  M2와 knn_seed 엣지(강도 0.72)가 깔린다. 등산과 카페가 정말 관련이 있는지는
  아무도 판단하지 않았다 — 가설이다.

### 7.2 인출 — "요즘 등산 어때?"에 카페 얘기가 딸려 나오는 이유

위 상태에서 사용자가 "요즘 등산 어때?"라고 묻는다. (α=1, β=0.3 가정)

1. 벡터 시드가 C(등산, 쿼리 유사도 0.85)를 잡는다.
2. 1-hop 확장이 C의 엣지를 따라 M2(카페)를 후보에 올린다.
3. M2의 점수: α항은 낮다(쿼리 "등산"과 카페의 유사도 ≈ 0.3). 그러나 β항 =
   유효엣지강도 0.72 × 시드 유사도 0.85 ≈ 0.61에 가중치 0.3을 곱해 0.18을
   더한다. 합산 순위에서 M2는 "등산과 무관하지만 표면 유사도가 어중간한" 다른
   노드들을 제친다.
4. M2가 상위 N에 들면, 응답을 만드는 쪽은 등산 얘기를 하면서 "카페에서 일하기
   좋아하는 사용자"라는 맥락을 함께 쥔다. 그리고 그 순간 C–M2 엣지가 bump를
   받는다 — 가설이 한 번 검증됐다.

이 과정이 반복되면 C–M2는 확정급 강도를 넘어 굳는다. 반대로 이 연결이 한 번도
쓸모를 증명하지 못하면, λ가 켜진 환경에서는 조용히 가라앉아 β항에서 사라진다.
어느 쪽이든 **아무도 이 엣지의 진실을 명시적으로 판정하지 않았다** — 사용이
조각했다.

### 7.3 딸려 나오지 않는 경우 넷

이웃 노드가 함께 소환되지 않는 이유는 넷 중 하나다:

1. **엣지가 없다** — 시드와 연결이 없으면 β = 0. 후보군에조차 들지 않는다
   (자체 유사도로 시드가 되지 않는 한).
2. **엣지가 가라앉았다** — 오래 사용되지 않아 유효강도가 바닥이면, 연결은
   존재하지만 견인력이 없다.
3. **시드가 약하다** — β는 곱이다. 엣지 강도가 1.0이어도 그 시드 자체가 쿼리와
   0.2짜리 관련이면 견인력은 0.2 수준이다. "강한 연결"만으로는 부족하고, "지금
   대화와 관련된 것과의 강한 연결"이어야 한다.
4. **딸려왔지만 선발에서 탈락했다** — 후보에는 들었으나 score 합산이 상위 N에
   못 미친 경우. 더 관련 있고 더 강한 기억들이 자리를 차지했다.

### 7.4 엣지의 일생

```
[탄생]     가설로 태어난다 (강도 = 유사도, 낮은 확신)
   │
   ├─ 사용됨 ──→ bump 누적 ──→ 확정급 추월 ──→ 상한(1.0) 포화
   │                                             │ 계속 쓰이면: 시계가 리셋되며 유효 1.0 유지
   │                                             │ 안 쓰이면: 유효강도만 침강 (저장값은 1.0)
   │                                             └ 다시 쓰이면: 시계 리셋 → 즉시 유효 1.0 부활
   │
   └─ 안 쓰임 ──→ (λ>0) 유효강도 침강 ──→ β 기여 소멸 = 랭킹에서의 자연사
                   행은 남는다. 삭제는 없다.
```

저장 강도가 내려가는 쓰기는 시스템에 존재하지 않는다. "약해짐"은 전부 읽기
시점의 유효강도에서 일어나며, 그래서 모든 침강은 가역이다.

## 8. 애플리케이션 통합 계약

이 시스템의 사용 계약은 한 문장이다: **애플리케이션은 판단하지 않고 던진다.
메모리가 판단한다.**

애플리케이션이 공급하는 것:

- **상호작용 원문** — 대화 메시지든 에이전트 세션 로그든, 무엇을 저장할지 고르지
  않고 최근 기록을 그대로 넘긴다. 추출·중복 검사·연결·강화는 전부 패키지가
  수행한다.
- **entityId** — 기억의 격리 단위. 모든 조회·판정은 엔티티 안에서만 일어난다.
- **LLM 어댑터와 임베딩 서비스** — 패키지는 모델을 소유하지 않는다.
- **튜닝 값** — 6장의 다이얼들. 요청 단위로 주입되므로 값 변경이 즉시 반영된다.
  넘기지 않은 필드는 패키지 기본값을 쓰고, 잘못된 값은 검증기가 기본값으로
  되돌린다.

애플리케이션이 받는 것:

- **작업 세트** — 인출 시점의 상위 N개 기억. 어시스턴트의 응답 프롬프트에 "지금
  기억하고 있는 것"으로 주입하는 용도다. 어떤 기억이 실제로 응답에 쓰였는지를
  애플리케이션이 보고할 필요는 없다 — 사용 신호는 인출 단위로 패키지가 이미
  기록했다.

전형적인 요청 흐름:

```
응답 생성 전:  getContext(최근 대화) ──→ 작업 세트 N개 ──→ 프롬프트에 주입
                                  └ (부수효과) 사용 기록, 기여 엣지 bump

응답 생성 후:  afterResponse(최근 대화) ──→ 패키지가 자체 인출로 작업 세트 구성
                                        ──→ 추출 LLM이 사실 추출 + 관련 지목
                                        ──→ 게이트 통과 → 저장·강화·시딩·유예
```

두 단계 모두에서 애플리케이션의 역할은 대화를 넘기는 것뿐이다. 저장 여부의 판단,
중복의 처리, 연결의 형성과 소멸은 모두 이 문서가 설명한 메커니즘이 수행한다.

## 9. 경계 — 이 문서 밖에 있는 것

- **병합 심사 워커** — 회색지대가 적재하는 장부(sleep_jobs)의 소비자. 큐 적재까지가
  현재 구현이며, 심사(병합/갱신/양립/무관 판정)는 후속 컴포넌트다.
- **감쇠의 기본 활성화** — λ의 기본값은 0(꺼짐)이다. 값의 선택은 운영 데이터
  (사용 간격 분포, 강화 유입률, 포화율)를 근거로 하는 운영 결정이다.

두 항목 모두 이 문서의 원리(ΔN 비례 비용, 소프트 판단, 사용이 조각)를 그대로
따르는 확장이며, 새 원리를 도입하지 않는다.
